Fresh-Context Review Agents

Reviewing code, plans and findings with an isolated agent that sees only the artifact — never the conversation that produced it. The mechanism is decontamination: an agent that watched the code get written reviews its own reasoning; a fresh agent reviews the code. Same model, meaningfully different results.

What the knob buys
Three knobs, not one setting
This carries the dial marker, so there is no regime that makes it the wrong call and no second panel naming one — what changes with the regime is where you set it. Effort level (low → max) trades false-positive rate against coverage per review. Local /code-review versus the hosted “ultrareview” trades depth against cost. And what the reviewer is shown — diff-only, diff + relevant files, or diff + task description — tunes isolation against context, which the framing-bias finding turns from a preference into a real per-task decision. These are genuine per-task knobs, not a fixed architectural commitment.
What the knob costs
speed-delta: −1
An explicit review pass — even a backgrounded one — adds wall-clock before merge that same-session “looks fine, ship it” does not. Claude Code's hosted reviews average 20 minutes; the local subagent is faster but still not instant. This is the axis the technique spends to buy quality, and it is charged at every position of the dial. It is expected for a verification step rather than a flaw — but it is the reason a hard latency-bound regime is the weakest fit, narrowed only partly by findings arriving asynchronously rather than blocking.

A trade by vector, a dial by marker

The note's own verdict is “Class: trade, with a dial.” Both halves are recorded here, and both are correct. Read off the delta vector this is a trade: it is not no-regret, because it spends wall-clock (and some tokens) to buy quality and to convert delegated-generation's verification burden into something cheaper to triage. The frontmatter also carries dial: true.

Those are not in tension. The program's rubric is explicit that dial is the only non-derivable class marker and is orthogonal to the other two: no-regret and trade are read off the vector and are mutually exclusive with each other, while dial sits on top of either. Recording both is following the rubric, not contradicting it — this page leads with the marker the vector cannot express, and the trade is spelled out in the deltas below it.

The knobs are real ones: review effort level, local versus hosted depth, and — the one this note argues is under-explored — how much narrative context the reviewer is handed at all.

quality-delta
+1
Not +2, deliberately

The Cross-Context Review experiment is the first non-anecdotal evidence for this note's core claim. A fresh session containing only the artifact plus a standard review prompt (CCR) was tested against same-session self-review (SR), repeated same-session self-review (SR2), and same-session review with the original generation prompt attached (SA). Across 30 artifacts with 150 deliberately injected errors, CCR scored 28.6% F1 against 24.6% (SR), 21.7% (SR2) and 23.8% (SA) — all differences significant at p ≤ 0.008. The edge was largest on critical-severity errors (+11 points) and on code artifacts specifically (+4.7 F1 points over SR).

The SR2 result is the load-bearing detail. Reviewing twice in the same session did not beat reviewing once — which rules out “more review passes” as the explanation and isolates the benefit to context separation itself. Without production history, a model has no memory of authoring the artifact, so sycophancy and self-preference bias lose their trigger.

It stops at +1 for two reasons. The absolute F1 numbers are still low — under 30% even for the best condition, meaning most injected errors were missed by every condition. And the framing-bias paper shows freshness alone does not fix everything: metadata framing still collapses detection in a fresh-context reviewer. A real, measured lift on a genuinely bad baseline; not a solved problem.

cost-delta
0
A wash against this baseline, not against none

A second full review pass over the diff is additional tokens the self-review baseline does not spend. But it is small relative to the size of the original generation — reviewing a diff is cheaper than writing it — and it is a fixed, bounded add rather than something that scales with retries the way multi-agent debate does.

One real exception, kept on the record rather than smoothed away: Anthropic's hosted Code Review is billed separately at $15–25 per review, which is a genuine cost if adopted at that tier. The local /code-review subagent path is ordinary session token spend. Net: roughly a wash against a baseline where some review already happens — and a clear cost if compared to no review at all, which is not the baseline stated here.

Paired with effort: low, that makes this one of the cheapest interventions on this site to adopt: most harnesses already ship review subagents or slash-command reviews, so it is config rather than infrastructure. What it actually spends is wall-clock. It is not literally free of tokens — the review pass is real spend — it just does not show up as a net regression against the stated baseline.

attention-delta
+1
The mitigation another note asked for

This is the axis Context Management via Subagents flagged as the bottleneck it creates — delegated generation means more human verification burden — and this note is its stated mitigation. A structured findings list (file:line, severity, one-sentence summary, ReportFindings-shaped output) is faster for a human to triage than re-reading a full diff cold.

Anthropic's hosted product goes further: severity-ranked, deduplicated, verified-against-actual-behavior findings posted inline, with a one-click 👍/👎 loop instead of prose to parse. It does not eliminate the human check — it makes each check cheaper, which is the specific claim the subagent note needed a mitigation for.

Cross-Context Review paper, arXiv
arxiv 2603.12123
Cross-Context Review: Improving LLM Output Quality by Separating Production and Review Sessions

Controlled experiment (30 artifacts, 150 injected errors, 4 review conditions) found fresh-session review beats same-session self-review on F1 (28.6% vs 24.6%), and that repeating the review in the same session doesn't recover the gap — isolating “context separation” as the actual mechanism, not just “review more.”

Nuances
Contextual Bias in LLM-Assisted Security Code Review, arXiv
arxiv 2603.18740
Measuring and Exploiting Contextual Bias in LLM-Assisted Security Code Review

Even a single fresh-encounter reviewer is highly susceptible to framing bias from PR metadata (titles/descriptions), with detection rates collapsing under a “looks safe” framing and recovering fully once metadata is redacted — so freshness alone isn't sufficient; what the reviewer is shown (diff-only vs. diff+narrative) matters as much as whether the session is fresh. One model's detection fell from 97% to 3.6% under a “looks fine” framing.

What would move this to measured
Everything above is desk research — the CCR paper, the framing-bias paper, and Anthropic's own product docs — with no hands-on trial in this codebase. Moving to measured means running the note's own comparison on real diffs from actual work rather than synthetic injected errors, and two hypotheses are queued for it. First: diff-only versus diff-plus-task-description reviewer performance, sharpened by the framing-bias finding into a real prediction — a task description is exactly the kind of “looks fine” narrative framing that collapsed detection rates in that paper, so diff-only may not just be more isolated, it may be more accurate. Second: whether CrewAI-style same-agent guardrails quietly give up the isolation benefit unless a separate reviewer agent is deliberately wired, since CrewAI's default LLMGuardrail reuses the acting agent's own LLM.
