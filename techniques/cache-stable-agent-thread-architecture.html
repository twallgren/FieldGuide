Cache-Stable Agent Thread Architecture

Keeping the prompt prefix stable and the history append-only makes a long agent thread much cheaper and somewhat faster — and spends nothing to do it. Scoped to Claude Code and the Claude API.

What it does
Nothing gets worse
This is a no-regret, so there is no regime under which it is the wrong call and no second panel naming one. Nothing about the architecture spends quality, speed, or attention to buy the cost reduction. One caveat, and it is a scope caveat rather than a trade: the verdict is scoped to Claude Code and the Claude API, and should not be assumed to travel to every provider.
What it costs to set up
effort: medium
In Claude Code the pattern is handled automatically — it is not something you configure, it is something you can break. The one-time cost lands on anyone hand-rolling a harness: keep the tool and system prefix identical and ordered across calls, append rather than rewrite history, and defer any tool schema not needed on turn one.

Why each delta reads the way it does

cost-delta
+2
The biggest single lever here

Cache reads bill at roughly 10% of the standard input-token rate — confirmed in Anthropic's tool-caching docs — and on a long thread most of each request is unchanged history and tool definitions. This is the single biggest lever on the token-cost axis for long-running threads.

Anthropic's own figures — a 100-turn Opus session with compaction dropping from $50–100 to $10–19 with caching — support an 80%-ish reduction in spirit. The widely circulated "92% cache hit rate / 81% cost reduction" figure does not appear in Anthropic's primary source; it comes from aggregator posts and should be treated as an unverified secondary-source number, not a confirmed Anthropic stat.

The pattern is corroborated independently rather than resting on one vendor's claim: LangChain's Deep Agents publishes its own measured numbers — 77% token-cost reduction on Claude Haiku, 80% on GPT-4 Mini, 49% on Gemini Flash.

speed-delta
+1
Not +2, deliberately

Cache reads process faster than full reprocessing. But wall-clock in most turns is dominated by generation time, not prefix reprocessing — a real but partial speedup, which is why it stops at +1.

quality-delta
0
A plumbing lever

Purely an economic lever. It changes what the request costs and how fast the prefix is reprocessed, not what information or capability reaches the model. That is consistent with the lever taxonomy treating this as a pure cache-efficiency payoff sitting outside the eight named mechanisms.

attention-delta
0
Two effects that cancel

In Claude Code the pattern is handled automatically, so there is no per-task attention cost for a normal user. But the behavioral hygiene it implies — don't switch model or effort mid-session, don't compact mid-task, prefer /rewind — is itself a vigilance tax if you are hand-rolling a harness. The awareness required roughly offsets the "don't have to think about it" benefit. Net neutral rather than a clear win either direction.

dial
false
A default, not a knob

There is no per-task setting to turn up or down here. Claude Code implements the architecture by default; what varies is whether you break it. Actions that invalidate the cache include switching /model or /effort mid-session, toggling fast mode, connecting or disconnecting a prefix-loaded MCP server, denying an entire tool via permissions, /compact, and upgrading Claude Code itself. Notably /rewind does not invalidate — it truncates back to an already-cached prefix, which is why it is cheaper than /compact when abandoning a path rather than genuinely needing to shrink context.

Cache-first agent design
Prompt Caching Economics: Cache-First Agent Design

OpenAI's July 9, 2026 GPT-5.6 rollout replaced free implicit caching with explicit breakpoints, a 1.25x cache-write premium, and a 30-minute minimum TTL — the cache-stable architecture pattern (stable prefixes, breakpoint budgets) still holds, but whether it's "free" savings or a genuine trade now depends on the provider, not just implementation discipline.

A gap left open
The mechanisms field is empty, and deliberately so. The mechanism here is economic — it is not one of the eight in the lever taxonomy, and it has the same shape as that taxonomy's existing "prompt caching doesn't fit" entry: a Context-lever intervention whose payoff is pure cache efficiency. Forcing a fit would have been the easier write-up and the less honest one, so the field was left blank and the gap flagged upstream instead.
