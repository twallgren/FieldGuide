Reach for it when
You run an agent at volume against a fixed benchmark
This is what the published versions are built for — teams with an eval set, a trace corpus, and enough run volume that a recurring failure pattern is worth mining. The full version is over-engineered for a solo, sabbatical-stage practice, whose regime is attention-bound and quality-bound. The version that does fit at that scale is small: a periodic pass that reads recent session transcripts for one project, looks for a recurring correction or friction point, proposes a one-line CLAUDE.md/SKILL.md edit as a diff, and stops there — staged for the user to accept, never auto-applied.
It is indefensible when
You would skip the validation gate
The gate is the load-bearing part, and Claude Code does not enforce it — it has to be built by hand, same as everywhere else. RHO is the demonstration of what skipping it looks like: self-preference as the only check, large reported gains, and no external grading anywhere in the loop. Drop the review and the attention cost arguably moves toward neutral, but the quality claim you were buying stops being trustworthy in the same motion.

Why each delta reads the way it does

quality-delta
+1
Not +2, deliberately

The published results are real and multi-source-corroborated: the Darwin Gödel Machine raised SWE-bench from 20.0% to 50.0% over generations; Self-Harness reported 14–21 point absolute gains on Terminal-Bench 2.0 from harness changes alone, base model held constant; RHO reported 59%→78% on SWE-Bench Pro; and Microsoft reports quality gains in its governed version too. That is genuine evidence this class of technique raises measured benchmark accuracy.

It is capped at +1 rather than +2 because none of this is measured by the user, all of it is vendor- or research-reported on benchmarks that may not transfer to the user's own repo, and the RHO result specifically should be discounted for using self-preference as its only check.

cost-delta
−1
Compute buys the gain above

Every implementation found spends real compute up front and continuing: replaying past trajectories (RHO), running an eval set across candidate harnesses (Self-Harness, Microsoft), or iterating generations of a coding agent against a benchmark (DGM). This is compute spent to buy the quality gain above, not free.

speed-delta
−1
A background loop, by construction

The loop is inherently async and batched — harvest, analyze, propose, validate, adopt — not something that speeds up the task in front of you right now. Every documented version treats it as a background or periodic process, which is slower per-cycle than just doing the task.

attention-delta
−1
The axis to weigh most carefully

This is the one to weigh hardest, given the thing is self-modifying. Even the most disciplined public Claude Code version found — nightly harvest, replay, validation gate, stage for review — still ends with a human reviewing a diff to their own operating rules before it goes live. That review is real, non-skippable attention if the gate is to mean anything, and RHO shows what happens when a team skips it.

This is the one place the note's original stated risk — the loop's own validation talking itself into loosening its own constraints — shows up concretely as a scored cost rather than as a caveat in prose.

effort
high
Four moving parts, none of them a flag

Every concrete instance found — DGM, Self-Harness, RHO, Microsoft's Agent Optimizer, even the disciplined Claude Code community pipeline — is a nontrivial engineering project. What that consists of, specifically: trace harvesting, eval-set curation, a validation gate, and a diff/rollback mechanism. Not a config flag. Nothing found ships this as a checkbox.

dial
false
A pipeline, not a knob

The deltas above are properties of the technique as typically built — self-triggered, infrequent, high setup cost — not a per-task knob you could turn up or down without re-engineering the pipeline.

the open risk
—
Quality and attention are coupled

The technique's measured quality gain and its attention cost are coupled through the validation step. Skip the review (RHO's approach) and attention-delta would arguably move toward neutral, but then quality-delta should be trusted less, per the self-preference concern. Keep the review (Microsoft's approach, the disciplined Claude Code pattern) and the quality claim gets more credible but the −1 on attention is the honest price.

There is no way to have both without a genuinely independent, cheap check. None of the four implementations found solved "independent check" more cheaply than "a human reads a diff" or "a separate eval set" — so a fresh-context reviewer as the automated version of that check remains an open idea worth trying, not something already solved elsewhere.

What Claude Code does and does not give you
There is no first-party, shipped "self-improving harness" feature in Claude Code as of this research — no built-in loop that reads its own transcripts and edits its own config automatically. The lever and mechanism are available: Hooks (SessionStart, Stop, SubagentStop) as the trigger, and Skills plus CLAUDE.md as the mutable surface. But the safety-relevant part — an independent validation gate before a self-proposed change goes live — is not something Claude Code enforces. It has to be built by hand, same as everywhere else.
