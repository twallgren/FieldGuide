History tracking began 28 Aug 2026. Any revisions before that date were not recorded, and are not reconstructed here.

Turn the knob down
Agent View, and nothing else
A few concurrent sessions — this program's own experiments — need nothing beyond claude agents: a terminal table of every background session grouped by state, a peek panel to answer the blocking question inline, and attach/detach on demand. Zero setup, no extra tokens, no infrastructure. At this end the technique trades nothing, which is why it is not a plain trade.
Turn the knob up
The OTel pipeline, and what it costs
A real multi-team fleet — or the cost-attribution goal specifically — justifies wiring CLAUDE_CODE_ENABLE_TELEMETRY=1 to a real backend and standing up collector plus Grafana or SigNoz plus retention. What that buys is historical, per-agent cost analysis Agent View does not cover. What it costs is real setup and real infrastructure. At this end the technique is no longer free.

Why each delta reads the way it does

attention-delta
+2
The highest in the corpus

This is the technique's whole point, and it is now backed by a concrete, shipped mechanism rather than a hypothesis. Agent View's peek panel exists specifically to answer “which of my N sessions needs me right now” without reading N transcripts. That is the “ops pager, not monitoring wall” framing from the note's key points, now realized.

The interesting design problem in this space is attention routing: surfacing the one agent that needs a human decision, not showing twenty progress bars. Since the answer is free and built into a tool already in use, this is close to a pure win on this axis — which is what earns a +2 where the other three axes sit at neutral or a single step.

speed-delta
+1
Not +2, deliberately

Faster time-to-notice-and-reply reduces the dead time an agent sits blocked waiting for input, which shortens wall-clock to an accepted outcome. Not +2 because the dashboard doesn't speed up inference or tool execution themselves — it only removes human-caused stalls, and only for the fraction of a run that's actually blocked on a human.

cost-delta
0
Neutral, and the spread is why

Agent View itself costs nothing beyond what the sessions would have cost anyway — no extra tokens, no extra infra. But the technique as a category ranges from that free case to a genuinely costly one (standing up an OTel collector plus Grafana or SigNoz plus retention), so scoring the category as a flat win would hide that spread.

Net: neutral, with the real cost story living in effort, not in this per-task delta. Read plainly — adopting this does not make your agent work cheaper.

quality-delta
0
Recorded 0, not guessed positive

Visibility into what agents are doing doesn't change what they produce. There's a plausible second-order argument — catching a stuck or off-track agent sooner prevents wasted output — but that's a Group 3 / Failure-cost effect, months-observable and not something this desk research can substantiate. It is recorded as 0 rather than guessed positive.

dial
true
Not a no-regret, not a trade

The technique spans a genuinely free tier — Agent View, use it or don't, no cost either way — through to a heavy custom fleet-observability stack, and which end makes sense is a per-situation call. A few concurrent sessions during this program's own experiments need nothing beyond Agent View; a real multi-team fleet, or the cost-attribution goal specifically, would justify the OTel pipeline.

That is exactly the “regimes change, and I know which knob does which” shape the evaluation dimensions flag as the strongest kind of finding — not a flat no-regret, because the heavy end has real setup cost, and not a single-axis trade, because the free end trades nothing.

Anthropic research, via TLDR AI
anthropic.com/research
Anthropic research on multi-agent systems

Anthropic's own research on multi-agent systems finds that individually benign agent behaviors can compound into systemic failures — confabulation, reward hacking, and unexpected dynamics — once many agents interact in shared environments, emerging faster than human institutions can oversee them. This is a caution against this note's implicit framing that better visibility (Agent View, cost-per-agent metrics) is sufficient to safely operate a fleet: some failure modes may only appear at scale and may not present as any single agent needing a human decision.

What the cost score does not cover
The cost-delta: 0 above was scored for the dashboard layer specifically — the cost of seeing a fleet. It was not scored for the compute and isolation cost of running one, which the concurrency writeup logged above suggests is the larger and less-visible number. Those are adjacent but distinct problems, and this note scores only the first. The gap is recorded rather than folded into a single figure that would have read as more complete than it is.
