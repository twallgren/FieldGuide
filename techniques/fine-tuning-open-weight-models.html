Fine-Tuning Open-Weight Models

Putting tribal knowledge in the weights ends the per-session context tax — and buys that with knowledge you can no longer diff, review, or selectively correct. The output gets worse on the axis that matters most when correctness matters.

Reach for it when
You are cost-bound or attention-bound
The two axes it actually improves. And only for the slice of knowledge it fits: style, vocabulary and conventions — the stable material, not the facts that change.
It is indefensible when
You are quality-bound
Indefensible under quality-bound regimes for anything beyond stable style and vocabulary, where the unreviewability cost dominates.

Why each delta reads the way it does

quality-delta
−1
The output is worse

Weights aren't diffable, reviewable, or selectively correctable the way a skill file is. This is the note's own stated catch, and the World Model Optimizer research pass sharpened it further — that tool's distillation path is opaque even about which technique it uses.

Set against the baseline's full reviewability, that is a real regression for anything where correctness matters, and worse for facts-that-change than for style and vocabulary. Knowledge in weights goes stale silently: the old "scan for conflicts" jobs have no weight-space equivalent short of retraining.

This is not a hypothetical cost to be noted and moved past. It is the thing being spent.

cost-delta
+1
Not +2 — retraining recurs

Once trained, a fine-tune removes the recurring per-session token cost of injecting the equivalent skill-file content, and MLX makes the training itself compute-free on hardware already owned (no GPU rental), so the marginal spend is mostly time, not dollars.

It stops at +1 because knowledge that changes forces retraining, which reintroduces recurring cost that files and retrieval never pay.

speed-delta
0
Two effects, cancelling

A trained model likely resolves style and vocabulary questions slightly faster per turn — less context to assemble and process than injecting the equivalent skill file. But that is roughly offset by the added latency of the offline curate-train-evaluate cycle whenever the corpus needs updating. No confident net direction either way.

attention-delta
+1
The stated thesis

This is the strategy's actual thesis: once trained, the knowledge is "just known," so there is nothing to curate, inject, or keep in the context window each session. The same "zero per-session cost" the technique leads with — now specifically an attention and context-budget win rather than a dollar one.

dial
false
An architecture decision

It is not a dial — it is an architecture decision made per knowledge-category (fine-tune the stable stuff, keep files for facts-that-change), not a per-task knob flipped at run time. Nor is it no-regret: the quality cost above is real rather than hypothetical, which is what makes this a trade and forces the regime question before anyone reaches for it.

World Model Optimizer

Reading the tool's own docs (not just the secondhand TLDR summary) sharpens the tension already logged below — WMO's distillation step runs through an opaque "Tinker API" with no documented technique (LoRA vs. full fine-tune isn't stated), and its main deliverable isn't a standalone fine-tuned model but a router that splits requests between a frontier model and the distilled small model to cut cost (claims 27% lower cost than frontier-only on RouterBench). That's a materially different bet than "replace context injection with weights": it's cost-optimization-via-routing with the small model as one leg, not a knowledge-in-weights play at all. Worth keeping distinct from the curated-LoRA plan rather than treating them as two implementations of the same idea.

World Model Optimizer (TLDR Dev item)

The "World Model Optimizer" OSS tool takes a different path to the same goal — instead of curated LoRA distillation from skill files, it turns collected agent traces into smaller optimized models via a closed-loop simulation-training process, with routing based on task traces. Worth weighing against the LoRA-on-curated-Q&A plan as a more automated but less reviewable alternative.

Placement
The intervention sits at the model lever — the change is to the weights themselves, not to the prompt, the loop, or the tooling around them — with capability and information as mechanisms: the model is made to know the material rather than be told it each session, which is exactly the substitution that removes the recurring context cost and removes the reviewability at the same time. One hedge the source names and this page will not bury: retrieval may beat fine-tuning outright for most of this. That is the author’s own wording, it is not scored, and it is not the baseline above — the baseline is context injection, which is what fine-tuning replaces. Retrieval is a third option that may dominate both, and a reader deciding whether to fine-tune should weigh it before weighing any number on this page.
