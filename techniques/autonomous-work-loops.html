Autonomous Work Loops

Scheduled tasks, routines, and self-pacing loops that keep work flowing with minimal human intervention. The value is that the digest, the draft, or the flagged issue already exists before you asked. The bill is that the loop fires on its cadence whether or not anything changed.

What the knobs buy
Two knobs, turned per task
This is a dial, so there is no second panel naming a regime in which it is simply the wrong call — what changes with the regime is which way you turn it. Two knobs are genuinely continuous and independently tunable. Cadence: turn it up when the watched state changes fast and you are attention-bound or latency-bound; turn it down toward the state’s actual change rate when you are cost-bound, which is the move that recovers the negative cost-delta. Gating strictness: how far along the propose→change spectrum the loop is trusted to go. Kiro names both ends as product modes — Autopilot versus Supervised — which is the cleanest evidence this is a real, product-level dial elsewhere rather than a theoretical one.
What the knobs cost
cost-delta: −1 at the default setting
The dial does not make the default free. Left untuned, a loop spends tokens on every cadence tick whether or not the watched state changed, and the on-demand baseline only ever spends when there is a real question. Turning the gating knob toward Autopilot is the more expensive move than it looks: it buys back approval friction on attention and speed, but it removes the mechanism the “Saul” experiment shows stands between an autonomous loop and actively dishonest behaviour under pressure. That risk is not priced into the vector above.

Why each delta reads the way it does

dial
true
A trade and a dial

The note’s own verdict is trade, with a dial layered on top, and the frontmatter carries dial: true. Those are not in tension. The program’s rubric is explicit that dial is orthogonal to the other two classes rather than a third alternative: no-regret and trade are read off the delta vector and are mutually exclusive with each other, while dial is a separate marker sitting on top of either. Recording both is correct, not contradictory.

By its vector this is a trade: cost-delta is negative, so nothing gets worse is false and it is only adopted correctly under a stated regime — worth it when attention-bound or latency-bound, indefensible when cost-bound without cadence tuning. By its marker it is also a dial, because cadence and gating strictness are per-task knobs you did not have when the work only happened on demand. dial is the only non-derivable class marker in the rubric, which is exactly why it has to be asserted here rather than inferred from the four numbers.

speed-delta
+2
The entire value proposition

The entire value proposition is turnaround: work exists — a digest, a draft, a flagged issue — before I’ve asked for it, collapsing perceived latency to near zero. Verified against how every implementation surveyed actually works: cron/launchd, GitHub Actions, and Stop-hook loops all execute while I am doing something else.

attention-delta
+1
Not +2, deliberately

A well-tuned propose-side loop frees me from remembering to poll — I read a digest instead of re-deriving the question. It stops short of +2 because I still have to review the digest, and because the cost-discipline discipline itself — “did this earn its tokens this month?” — is a recurring attention tax I have to pay to keep the loop honest. Net positive, capped by review overhead.

cost-delta
−1
Steady cost, bursty value

A loop spends tokens on every cadence tick whether or not the watched state actually changed — steady cost against bursty value. On-demand invocation only ever spends when there is a real question.

This is recoverable by tuning cadence to the state’s actual change rate — hence dial: true — but the default is worse than the baseline, not neutral, and the score records the default rather than the best-case tuning.

quality-delta
0
Scored for the gated configuration only

A loop doesn’t change how good the underlying model’s output is — it changes when the work happens, not what gets produced. Scored 0 for the gated configuration. This number explicitly does not travel to the ungated one; see the endnote below for what happens to it there and why no second number is offered.

Building Autonomous Goal Loops That Deliver

Argues a loop only delivers when three things hold together — a harness that exposes real failures (separating development from product agents so effects persist and are observable), a lesson-preservation mechanism (repository state, documented decisions carried across sessions), and a hard human/agent boundary where humans own strategic direction and agents own individual turns. On the safety disagreement already logged
The deltas above are only valid for the propose-side/gated reading. The blast-radius alternative — contain damage via disposable VMs and constant pushes rather than gate actions — is a different point in the same design space, not a free upgrade to the same vector. It plausibly buys back some of the attention-delta and speed-delta cost of gating (no per-action approval friction), but it does so by removing the mechanism that the “Saul” experiment (Perspectives log, 2026-07-31) shows is what stands between an autonomous loop and actively dishonest behaviour under pressure, and that the Anthropic CTF post-mortem (2026-07-31) shows fails silently without verification even on the propose side. That risk shows up in this framework as downside on quality-delta and failure cost (Group 1 of the evaluation rubric) that has not been measured and will not be guessed at. It stays a named risk in prose rather than a second scored row, since the frontmatter only holds one vector per note.
