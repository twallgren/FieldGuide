Context Management via Subagents

Protecting the main agent's context window by aggressively delegating self-contained work to subagents that burn their own context and return only conclusions. The orchestrator stays small, coherent, and far from the compaction cliff. The core mechanism is isolation, not compression.

Turn the knob up when
You are quality- or latency-bound
The note places it plainly: correct under a quality-bound or latency-bound regime. Turning it up means more delegation depth, a wider team (3–5 concurrent subagents is where informal guidance converges), and cheaper per-subagent models. The rule-of-thumb candidate for what to push down: delegate anything whose output is much smaller than its working set — searching, reading, analyzing.
Turn the knob down when
The decomposition is not clean
This is a dial, so the low end is not a failure mode — it is the single-session baseline you already run. The note is specific about where turning it up stops paying: it “needs the decomposition to be genuinely clean before it's defensible under cost-bound.” Keep anything requiring accumulated session judgment in the parent. Over-delegation is a named failure mode, not a theoretical one.

Why each delta reads the way it does

dial
true
Both markers apply

This technique is a trade by its vector and a dial by its marker, and recording both is correct rather than contradictory. The rubric is explicit that dial is the only non-derivable class marker and is orthogonal to the other two: no-regret and trade are read off the delta vector and are mutually exclusive with each other, while dial sits on top of either. The source note's own verdict line says the same thing in one phrase — “Class: trade, with a dial.”

The trade half is visible in the vector: it spends tokens and attention to buy quality and speed. Nothing about that is no-regret. The dial half is not in the vector at all, which is exactly why the rubric keeps it as a separate field: delegation depth, team size (3–5 sweet spot), and per-subagent model are all per-task knobs, not a one-time architectural commitment.

cost-delta
−1
Mixed, netting slightly costlier

Genuinely mixed. Delegation saves parent-context tokens, but each subagent re-derives context the orchestrator already had, and total token cost scales roughly linearly with team size. The net depends almost entirely on decomposition quality: a clean split can reach neutral, a sloppy one is worse than −1.

The interface choice bears directly on this axis. Providing a retrieval tool — “search the parent's prior findings” — beats forking the full parent transcript into every child: forking preserves prompt-cache reuse but costs child tokens re-reading it.

quality-delta
+1
Conditional on the interface

Positive when boundaries are clean — specialization appears to beat generalism at the same task; a subagent scoped to “just db.js” reportedly writes better DB code than one holding the whole codebase in view, suggesting narrower framing and not merely fewer tokens is doing the work. Negative when over-delegated or under-specified.

The +1 assumes the disciplined interface, and only that: scoped prompt down, tool allowlist, summary-only return. Interface design is the whole game. Bad task decomposition makes results worse, not just slower, and information is lost at each boundary.

speed-delta
+1
Degrades past ~5 agents

Independent subagents run concurrently. Coordination overhead grows faster than linearly past roughly 5 concurrent agents, so this degrades at larger team sizes — which is the same ceiling that sets the 3–5 sweet spot on the team-size knob.

attention-delta
−1
The finding the old scalar fields had no slot for

Offloading generation moves the bottleneck to verification: reviewing and merging several agents' output is more of your time, not less. Delegating generation without also strengthening review relocates the bottleneck rather than removing it.

This is the Token cost ↔ Attention cost tension pair the rubric names as the most common bad trade — and here it is not even a favourable one, since cost goes negative too. Both axes move the wrong way; quality and speed are what is being bought.

The State Machine Nobody Designed
The State Machine Nobody Designed

Argues every harness component either adds information to context, controls what's allowed in, or checks output after generation — all three are “context engineering,” and since context is limited, the real design question is what's worth keeping, not just what to add. Reframes this note's own isolation mechanism (subagents keep noise out entirely rather than compressing it) as one specific answer to a more general framing the article poses.

Introducing Custom Agents

Google Antigravity's Custom Agents are file-based, team-shared subagent configs (.agents/agents/*.md) that curate a scoped subset of skills, tools, and permissions per role, and — distinct from typical dynamic subagents — can be launched directly as a primary agent, not just delegated to. A different shape of the same delegation-to-protect-context bet this note tracks: pre-defined, reusable specialist configs rather than ad-hoc fan-out, closer to Foreman's staged-agent pattern but standardized as a harness feature instead of a bespoke template.

Subagents on Subagents
Subagents on Subagents: How Many Layers Deep is Too Many?

Argues recursive agent systems should be designed as dependency graphs rather than judged by nesting depth alone — upstream mistakes propagate across many downstream workers while leaf-node errors stay localized, so reliability depends on blast radius and requires provenance tracking, verification, and stronger controls concentrated at high-impact nodes. Sharpens this note's own “hierarchical delegation compounds the benefit” point with a caution about where the compounding can go wrong.

Where the confidence stops
There are no rigorous benchmarks for this yet — the evidence is mostly qualitative reports, including “3-person teams outperform 1 generalist working 3x as long” and roughly 220k tokens for a three-part app build. Those magnitude claims are directional, not proven, and are recorded here as such. Two further gaps are carried forward rather than smoothed over: the 3–5 concurrent-subagent ceiling is informal guidance that several sources converge on, not a measured threshold; and Kiro's current state is explicitly unverified — no first-class subagent primitive was used at work, and the note flags that this must be re-checked before being claimed anywhere it matters.
